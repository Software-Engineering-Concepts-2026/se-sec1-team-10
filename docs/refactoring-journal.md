# Refactoring Journal

## 1. Smell ที่เจอ (Code Smell Details)
**ชื่อ Smell:** Duplicate Code
**ตำแหน่งที่พบ:** ไฟล์ index.html และ chayakorn_Food Logging_prototype.html มีโค้ด CSS และ JavaScript ที่ทำหน้าที่คล้ายกัน
**สาเหตุที่เป็น Smell:** มีการเขียนโค้ดส่วนเดียวกันซ้ำในหลายไฟล์ ทำให้เมื่อมีการแก้ไขหรือเพิ่ม Feature ต้องแก้หลายจุด และอาจทำให้โค้ดของแต่ละหน้าไม่ตรงกันในอนาคต ส่งผลให้การดูแลรักษาและแก้ Bug ทำได้ยากขึ้น

## 2. AI Usage (การใช้งาน AI ร่วมกับทีม)
**Prompt ที่ใช้:** พบปัญหา Duplicate Code ระหว่าง index.html และ chayakorn_Food Logging_prototype.html ช่วยเสนอแนวทาง Refactor ที่เหมาะสม พร้อมข้อดีและข้อเสียของแต่ละวิธี
**AI Output:** AI เสนอแนวทาง Refactor 3 วิธี ได้แก่
- แยก CSS และ JavaScript เป็นไฟล์กลาง
- เลือกเก็บ Prototype หลักไว้เพียงไฟล์เดียว
- แยก Logic เป็น Function หรือ Module ที่สามารถนำกลับมาใช้ใหม่ได้
**ส่วนที่ทีมเขียนและตรวจสอบเอง (≥ 70%):** 
- ตรวจสอบว่าโค้ดของทั้งสองไฟล์มีส่วนใดที่ซ้ำกันจริง
- พิจารณาว่าทั้งสองไฟล์ยังจำเป็นต้องใช้งานอยู่หรือไม่
- เลือกแนวทางที่เหมาะสมกับโครงสร้างของ Prototype

## 3. Before / After Comparison
| ประเด็น              | Before (ก่อน Refactor)                        | After (หลัง Refactor)                  |
| -------------------- | --------------------------------------------- | -------------------------------------- |
| **Code Duplication** | มี CSS/JavaScript ซ้ำกันในหลายไฟล์            | ย้ายโค้ดที่ใช้ร่วมกันไปไว้ในไฟล์กลาง   |
| **การแก้ไขโค้ด**     | ต้องแก้ไขหลายไฟล์                             | แก้ไขที่ไฟล์กลางเพียงจุดเดียว          |
| **Maintainability**  | ดูแลยากและมีโอกาสเกิดความไม่ตรงกัน            | ดูแลและแก้ไขได้ง่ายขึ้น                |
| **Consistency**      | แต่ละไฟล์อาจมีโค้ดไม่เหมือนกันเมื่อมีการแก้ไข | ทั้งสองหน้าสามารถใช้ Logic เดียวกันได้ |

## 4. Lessons Learned (บทเรียนที่ได้รับ)
- ได้เรียนรู้ว่า Duplicate Code ไม่ได้เป็นเพียงปัญหาเรื่องจำนวนบรรทัดของโค้ด แต่ทำให้การแก้ไขและบำรุงรักษาระบบทำได้ยากขึ้น
- การแยก CSS และ JavaScript ที่ใช้ร่วมกันออกมาเป็นไฟล์กลางช่วยลดการเขียนโค้ดซ้ำ และทำให้โครงสร้างโปรเจกต์เป็นระเบียบมากขึ้น
- Workflow Explain → Propose → Apply → Test ช่วยให้เข้าใจปัญหา ก่อนลงมือ Refactor และตรวจสอบว่าระบบหลัง Refactor ยังทำงานได้ถูกต้อง
