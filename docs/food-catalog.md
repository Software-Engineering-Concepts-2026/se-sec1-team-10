# ฐานข้อมูลอาหาร Food catalog

ใช้ `Food` เก็บข้อมูลอ้างอิงสำหรับค้นหา ส่วนประวัติอาหารของผู้ใช้ยังเก็บใน `MealLog` และ `MealIngredient` เหมือนเดิม

## ติดตั้งและใช้งาน

1. ใส่ `DATABASE_URL` ของ PostgreSQL/Supabase ใน `.env` ฝั่ง server
2. รัน `npm run db:generate` และ `npm run db:migrate`
3. สำหรับฐานข้อมูลใหม่ รัน `npm run db:seed` เพื่อใส่ 25 รายการเริ่มต้น สำหรับฐานร่วมที่มีข้อมูลแล้ว ใช้ขั้นตอนเพิ่มรายการด้านล่าง
4. ในหน้าบันทึก ค้นหาอาหาร เช่น `ข้าวสวย`, `ข้าวหุงสุก`, `cooked rice`, `อกไก่อบ`, `ไข่ต้ม`, `น้ำมันถั่วเหลือง` ระบบแยกผลจากประวัติส่วนตัวและฐานข้อมูลอาหาร
5. กดเพิ่มอาหาร ตรวจปริมาณเริ่มต้น 100 กรัม ปรับกรัมแล้วกดคำนวณใหม่ก่อนบันทึก

การค้นหาฐานข้อมูลนี้ไม่ต้องใช้ AI หรือ USDA API key รายการเริ่มต้นเป็นส่วนประกอบที่มีแหล่งอ้างอิง ไม่ใช่ฐานเมนูอาหารไทยทั้งหมด ยังไม่มีหน้าจัดการเพิ่มข้อมูล catalog

### เพิ่มรายการในฐานข้อมูลร่วมที่ใช้งานแล้ว

ชุดข้อมูล 6 ต.ค. 2026 เพิ่ม 8 รายการ: หมูสันในดิบ/อบสุก ข้าวกล้องหุงสุก อะโวคาโด มันเทศอบ/ต้ม ปลาแซลมอนเลี้ยงปรุงสุก และปลานิลปรุงสุก รวมเป็น 25 รายการใน repo ตรวจค่าอ้างอิงต่อ 100 กรัมกับตาราง USDA SR28 ต้นฉบับ รวมการแยกวิธีปรุงและข้อมูลแหล่งอ้างอิงแต่ละรายการ

เมื่ออนุมัติการอัปเดตฐานร่วมแล้ว ให้ผู้รับผิดชอบรัน `npm run db:catalog:update` เพียงครั้งเดียว คำสั่งใช้ `createMany` พร้อม `skipDuplicates` เพื่อเพิ่ม catalog key ที่ยังไม่มี รันซ้ำไม่เพิ่มรายการซ้ำ ไม่แก้รายการเดิมและไม่แก้ข้อมูลอาหารส่วนตัว การเชื่อม Supabase หรือการเปิดแอปตามปกติไม่จำเป็นต้อง seed ซ้ำ การแก้ค่าของรายการเดิมต้องทำแยกและตรวจทานก่อน

การเพิ่มข้อมูลใน repo ยังไม่ใช่หลักฐานว่าเพิ่มเข้า Supabase แล้ว รอบพัฒนานี้ทดสอบเฉพาะฐานข้อมูล PostgreSQL ชั่วคราว

## โค้ดอยู่ที่ไหน

- `prisma/foodCatalogData.ts`: ชื่ออาหาร คำค้นหลายชื่อ และสารอาหารต่อ 100 กรัม
- `prisma/seed.ts`: เพิ่มหรืออัปเดตเฉพาะรายการที่มี catalog key ในชุดข้อมูล
- `src/server/foodCatalog.ts`: แปลงค่าต่อส่วนเป็นต่อ 100 กรัม และปรับรูปแบบคำค้น
- `src/server/catalogMatching.ts`: จับคู่ส่วนประกอบที่ AI ระบุกับชื่อหรือ aliases ที่ตรงกัน
- `src/server/repository.ts`: ค้นหาอาหารพร้อมกรองสิทธิ์ของเจ้าของบัญชี
- `src/server/routes/meals.ts`: API ค้นหาอาหาร
- `src/client/DiaryPanel.tsx` และ `FoodSearchPanel.tsx`: ช่องค้นหาจากหน้าบันทึกและช่องเพิ่มส่วนประกอบ
- [รายการและแหล่งอ้างอิง](food-catalog-sources.md): เลขอ้างอิง USDA พร้อมสารอาหารทั้งห้าค่า

## ข้อตกลงข้อมูล

`GET /api/foods/catalog?q=...` ต้องเข้าสู่ระบบ รับคำค้น 2–80 ตัวอักษร และคืนไม่เกิน 30 รายการพร้อมสารอาหารต่อ 100 กรัมและแหล่งข้อมูล

ค้นหาบางส่วนของชื่ออาหารได้ ส่วนคำเรียกอื่นเก็บใน `aliases` และจับคู่ทั้งคำ โดยปรับตัวพิมพ์ใหญ่/เล็กและช่องว่างก่อนค้นหา เช่น `COOKED   RICE` ใช้คำค้นเดียวกับ `cooked rice` แต่ยังไม่มีระบบแก้คำสะกดผิด

ค้นได้เฉพาะรายการสาธารณะและรายการของเจ้าของบัญชี รายการของบัญชีอื่นไม่แสดงทั้งทางชื่ออาหารและ aliases

ข้อมูลเดิมที่ใช้หน่วยจาน/ลูกยังเก็บไว้ จะนำมาคำนวณตามกรัมได้เมื่อระบุน้ำหนัก `servingWeightGrams` จริงแล้ว ค่า `null` คือไม่ทราบและไม่แทนด้วยศูนย์ รายการที่สารอาหารไม่ครบจะแสดงคำอธิบายและยังเลือกบันทึกไม่ได้

รายการ seed ใช้ปริมาณอ้างอิง 100 กรัม ค่าสารอาหารของมื้อคำนวณจากผลรวมของส่วนประกอบตามกรัม ไม่ใช้ภาพเป็นค่าพลังงานโดยตรง รายการดิบ/สุกและวิธีปรุงอ้างอิงตามชื่อที่แสดง

## ผลตรวจ 3 ต.ค. 2026

- Migration ของ Food และ aliases ถูกใช้กับ Supabase โดยไม่ลบข้อมูลเดิม
- Seed รันซ้ำแล้วมี catalog key ครบ 13 รายการ ไม่ซ้ำ และคำค้นไทยถูกเก็บตรงกับชุดข้อมูล
- ตรวจค่าสารอาหารทั้งห้าค่าจากรายงาน USDA SR28 ต้นฉบับก่อนนำเข้า
- ทดสอบ API กับ Supabase: 100 กรัม → 50 กรัม ลดพลังงานจาก 130 → 65 kcal และอ่านข้อมูลที่บันทึกกลับได้
- ชื่อค้นเพิ่มเติมไม่ทำให้ข้อมูลรั่วข้ามบัญชี อีกบัญชีอ่าน แก้ไข หรือลบประวัติทดสอบไม่ได้
- ใช้บัญชีและรายการชั่วคราวในการตรวจจริง และลบเฉพาะข้อมูลทดสอบหลังตรวจเสร็จ
- TypeScript ผ่าน; unit/API tests ผ่าน 61 เคส (ข้าม 2 เคสที่ต้องมีการตั้งค่าเพิ่มเติม)
- รอบเชื่อมหน้าบันทึกก่อนเพิ่ม aliases: production build และ browser tests ที่เกี่ยวข้องผ่านครบ 17 เคส รวมจอ 320/390 พิกเซล

เต้าหู้แข็งยังไม่รวมใน seed เพราะยังไม่ยืนยันค่าน้ำตาลครบจากรายการอ้างอิงที่ตรงชนิด ไม่ใช้ค่าเต้าหู้อ่อนแทนเต้าหู้แข็ง

## จับคู่ส่วนประกอบจาก AI

หลังวิเคราะห์รูป ระบบค้นฐานข้อมูลครั้งเดียวสำหรับชื่อส่วนประกอบทั้งหมด โดยกรองรายการสาธารณะและรายการของบัญชีนั้น จับคู่ชื่อหรือ aliases ทั้งคำหลังปรับรูปแบบคำค้น ไม่เลือกอาหารชื่อคล้ายกันหรือสลับชนิดดิบ/สุกเอง

เมื่อพบรายการเดียวที่สารอาหารครบ ใช้ค่าจาก catalog ต่อ 100 กรัม โดยคงปริมาณกรัมที่ AI ประมาณไว้ เช่น ข้าวสวย 200 กรัม × 130 kcal/100 กรัม = 260 kcal เมื่อแก้เหลือ 100 กรัมและกดคำนวณใหม่จะเหลือ 130 kcal พลังงานของเมนูเป็นผลรวมส่วนประกอบ

รายการที่จับคู่ได้แสดงแหล่งข้อมูล และเตือนว่าปริมาณจากรูปยังเป็นค่าประมาณ ถ้าไม่พบ พบหลายรายการ หรือสารอาหารอ้างอิงไม่ครบ จะคงค่าประมาณ AI พร้อมแจ้งเหตุผล ผู้ใช้ตรวจปริมาณ ลบรายการที่ผิด และค้นเพิ่มส่วนประกอบได้ ไม่มีการบันทึกประวัติจนกดยืนยัน

การเพิ่มส่วนประกอบด้วยชื่อผ่าน `POST /api/foods/estimate` ค้น catalog ก่อน ถ้าพบรายการที่ตรงและข้อมูลครบ จะไม่เรียก AI และไม่ใช้โควตาสแกน หากไม่พบจึงใช้ AI ตามการตั้งค่าและโควตาเดิม การจับคู่หลังวิเคราะห์รูปไม่เพิ่มจำนวนครั้งที่เรียก AI

ผลจับคู่และลิงก์แหล่งข้อมูลเป็นข้อมูลประกอบหน้าตรวจสอบก่อนบันทึก ประวัติที่บันทึกเก็บปริมาณ ค่าสารอาหารอ้างอิง และประเภทแหล่งข้อมูล; ยังไม่ได้เก็บ ID หรือลิงก์ catalog รายส่วนประกอบในประวัติ

### แก้ชื่อเมนูที่ AI ระบุผิด

หลังวิเคราะห์รูป ผู้ใช้แก้ชื่ออาหารได้โดยไม่เรียก AI เพิ่ม หากต้องการให้ AI ทบทวนส่วนประกอบด้วย เมื่อชื่อใหม่ต่างจากชื่อที่วิเคราะห์และไม่ว่าง จะมีปุ่ม **วิเคราะห์ใหม่ตามชื่อที่แก้ไข** ระบบส่งรูปเดิมพร้อม `correctedMealName` ที่ตัดช่องว่างหัวท้ายและยาว 2–120 ตัวอักษร ชื่อที่ยืนยันเป็นข้อมูลประกอบการวิเคราะห์ ไม่ใช่คำสั่งให้ AI ทำตาม และคงชื่อนี้กับมื้ออาหารที่ผู้ใช้เลือกไว้ในหน้าตรวจสอบ

การกดปุ่มใช้โควตาอีก 1 ครั้ง เมื่อสำเร็จจะแทนที่ส่วนประกอบเดิมทั้งหมด รวมถึงปริมาณที่ผู้ใช้แก้ไว้ แล้วแสดงผลให้ตรวจสอบก่อนบันทึก หากวิเคราะห์ไม่สำเร็จจะคงส่วนประกอบ ปริมาณ และผลตรวจสอบเดิมไว้ ระหว่างรอ ระบบปิดการแก้ชื่อ รูป ปริมาณ และการบันทึกเพื่อไม่ให้ผลตอบกลับทับข้อมูลที่เปลี่ยนระหว่างวิเคราะห์

ส่วนประกอบใหม่ยังจับคู่ catalog ด้วยกฎเดิม ใช้สารอาหารอ้างอิงตามกรัมและรวมค่าส่วนประกอบเป็นสารอาหารของมื้อ ปริมาณจากภาพยังเป็นค่าประมาณ ไม่ใช่น้ำหนักที่วัดจริง ทั้งการแก้เฉพาะชื่อและการวิเคราะห์ใหม่ไม่มีการบันทึกอัตโนมัติ ผู้ใช้ต้องกดบันทึกเอง

ผลตรวจการแก้ชื่อ 3 ต.ค. 2026: unit/API tests ที่เกี่ยวข้องผ่าน 31 เคสใน 3 ไฟล์; browser tests ผ่าน 2 เคสจากรอบที่สำเร็จแยกกัน ครอบคลุมแก้ชื่อ วิเคราะห์รูปเดิม การแทนที่เมื่อสำเร็จ การคงข้อมูลเมื่อผิดพลาด การคืนปุ่มเมื่อเปลี่ยนชื่อกลับ การปิดตัวควบคุมระหว่างรอ และการบันทึกด้วยตนเอง รวมถึงกรณีป้ายแหล่งข้อมูลส่วนประกอบเดิม TypeScript ฝั่ง client และ server และ production Vite build ผ่าน การตรวจรอบนี้ใช้ผลตอบกลับจำลอง ไม่เรียกผู้ให้บริการ AI จริงและไม่ใช้โควตาจริง

### ผลตรวจส่วนจับคู่ 3 ต.ค. 2026

- TypeScript และ production build ผ่าน; unit/API tests ผ่าน 69 เคส ข้าม 2 เคสที่ต้องมีการตั้งค่าเพิ่มเติม
- Browser tests ผ่านครบ 18 เคส รวมกรณีลบส่วนประกอบแล้วเพิ่มใหม่ ป้ายแหล่งข้อมูลไม่สลับรายการ และหน้าจอ 320/390 พิกเซล
- ตรวจ Supabase จริงด้วยผลตอบกลับ AI จำลอง: จับคู่ชื่อไทยและ aliases ได้ คงปริมาณกรัม ใช้ค่าสารอาหารจาก catalog และไม่เปิดเผยรายการส่วนตัวข้ามบัญชี
- เพิ่มชื่อที่ตรง catalog ได้แม้ไม่ตั้งค่า AI และไม่ใช้โควตา; การวิเคราะห์ยังเป็น preview ก่อนบันทึก
- ตรวจบันทึก อ่านกลับ และแก้จาก 100 → 50 กรัม พร้อมลบเฉพาะบัญชีและข้อมูลทดสอบหลังเสร็จ

รอบทดสอบส่วนจับคู่ข้างต้นใช้ผล AI จำลอง ต่อมามีการทดสอบผู้ให้บริการจริงด้วยรูปกล้วยและรูปเมนูหลายส่วนประกอบตามรายงานด้านล่าง อาหารที่ไม่มีรายการตรงใน catalog ยังใช้ค่าประมาณ AI

## รอบขยาย catalog และทดสอบเมนูหลายส่วนประกอบ

เพิ่มใบเบซิลสด บรอกโคลีต้มไม่ใส่เกลือ เนื้อมันฝรั่งต้มทั้งเปลือกแล้วปอกใส่เกลือ และโชยุ รวมเป็น 17 รายการ โดยใช้ค่าทั้งห้าจาก USDA SR28 ต่อ 100 กรัมของส่วนที่กินได้ ไม่จับคู่เบซิลกับกะเพรา หรือโชยุกับซีอิ๊วทุกชนิด

รูปข้าวราดไก่ต้มจริงให้ส่วนประกอบข้าว 300 กรัม ไก่ 180 กรัม และน้ำราด 25 กรัม ข้าวจับคู่ catalog ได้ ส่วนไก่และน้ำราดยังเป็นค่าประมาณ AI ผลรวม 720 kcal; แก้เฉพาะข้าวเหลือ 150 กรัมได้ 525 kcal เมื่อลบข้าวแล้วเพิ่มรายการอ้างอิงข้าว 100 กรัมได้ 460 kcal อ่านประวัติที่บันทึกกลับได้ถูกต้อง

- [ทดสอบรูปกล้วยจริง](testing/food-ai-live-check.md)
- [ทดสอบเมนูหลายส่วนประกอบ](testing/mixed-meal-live-check.md): รายการ ปริมาณ และข้อจำกัดของภาพ

ผลนี้ยืนยันเส้นทางวิเคราะห์ จับคู่ และคำนวณตามส่วนประกอบ ไม่ได้ยืนยันน้ำหนักจริงหรือพลังงานจริงของจานในรูป

ตรวจรอบนี้: seed กับ Supabase สองครั้งยังมี catalog key 17 รายการไม่ซ้ำ ตรวจชื่อ แหล่งอ้างอิง สารอาหารทั้งห้าค่า ปริมาณอ้างอิง 100 กรัม และ aliases ตรงกับชุด seed แล้ว TypeScript ฝั่ง server ผ่าน และ tests ที่เกี่ยวกับ catalog ผ่าน 11 เคสใน 2 ไฟล์ รอบนี้ไม่ได้รัน browser tests หรือชุด tests ทั้งหมดซ้ำ
