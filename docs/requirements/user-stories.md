# User Stories

เอกสารนี้รวบรวม User Stories ของระบบติดตามและจัดการสุขภาพ โดยอ้างอิงจาก GitHub Issues ของทีม และเชื่อมโยงกับ Personas และ Scenarios ของโครงการ

> **สถานะเอกสาร:** User Stories และ Priority ด้านล่างเป็น snapshot จากการวางแผน/Issues เดิม ใช้เป็นแหล่งอ้างอิงข้อกำหนด ไม่ได้ยืนยันการส่งมอบหรือเป็นการตกลงปรับ Priority ใหม่ ขอบเขตที่มีในระบบปัจจุบันให้ยึด [คู่มือผู้ใช้](../user-guide.md) และ [เอกสารสถาปัตยกรรม](../architecture/README.md)

## Story US-01: สมัครสมาชิก

**Source Issue:** #4\
**Source Scenario:** SC-01\
**Persona:** คุณปกรณณ์ (กรณ์)

As a คุณปกรณณ์ (กรณ์)\
I want สมัครสมาชิก\
So that ฉันสามารถบันทึกและติดตามข้อมูลสุขภาพของตนเองได้

**Acceptance Criteria**

- [ ] AC1: ผู้ใช้สามารถกรอกข้อมูลที่จำเป็นสำหรับการสมัครสมาชิกได้
- [ ] AC2: ระบบตรวจสอบว่าข้อมูลที่จำเป็นถูกกรอกครบก่อนสมัคร
- [ ] AC3: หากข้อมูลไม่ถูกต้อง ระบบแจ้งข้อผิดพลาดให้ผู้ใช้ทราบ
- [ ] AC4: เมื่อสมัครสำเร็จ ระบบสร้างบัญชีผู้ใช้และสามารถเข้าสู่ระบบได้

**Priority:** Must\
**Estimate:** M

## Story US-02: แก้ไขข้อมูลส่วนตัว

**Source Issue:** #6\
**Source Scenario:** SC-01\
**Persona:** คุณปกรณณ์ (กรณ์)

- [ ] AC4: ระบบแสดงข้อมูลส่วนตัวล่าสุดหลังจากบันทึกสำเร็จ

# Quality Bar

ก่อนเพิ่ม User Story ใหม่ ทีมควรตรวจสอบคำถามต่อไปนี้:

1. **Independent** — Story สามารถพัฒนาและทดสอบได้โดยไม่ต้องพึ่งพา Story อื่นที่ไม่จำเป็นหรือไม่?
2. **Coherent** — Story สอดคล้องกับ Persona และ Scenario หรือไม่?
3. **Relevant** — Story ตอบปัญหาหรือความต้องการของผู้ใช้หรือไม่?
4. **Measurable** — Acceptance Criteria สามารถตรวจสอบผลลัพธ์ได้หรือไม่?
