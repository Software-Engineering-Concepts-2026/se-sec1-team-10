# เป้าหมาย TDEE และการติดตามผล

ผู้ใช้เปิดบัญชี → เป้าหมายสุขภาพ โดยระบบแสดง TDEE ก่อนเลือก รักษาน้ำหนัก/สมดุล ลดน้ำหนัก หรือเพิ่มกล้ามเนื้อ ต้องมีอายุ น้ำหนัก ส่วนสูง และเลือกเพศสำหรับสูตรกับระดับกิจกรรมอย่างชัดเจน ระบบไม่เดาเพศจากชื่อหรือบัญชี

## การประมาณและค่าตั้งต้น

ใช้สมการ resting energy ของ [Mifflin–St Jeor](https://pubmed.ncbi.nlm.nih.gov/2305711/) แบบย่อ `10 × น้ำหนัก + 6.25 × ส่วนสูง − 5 × อายุ + 5` สำหรับชาย และ `−161` แทน `+5` สำหรับหญิง จากนั้นคูณระดับกิจกรรม 1.4, 1.6 หรือ 1.8 เพื่อประมาณ TDEE ระดับเหล่านี้เป็น preset ของแอปภายในช่วงกิจกรรมทั่วไปของ [NIH Body Weight Planner](https://www.niddk.nih.gov/bwp) ไม่ได้ใช้แบบจำลองพยากรณ์น้ำหนักของ NIH

ค่าตั้งต้นของแอป: รักษาน้ำหนัก 100% ของ TDEE, ลดน้ำหนัก 90%, เพิ่มกล้ามเนื้อ 105% เป็นจุดเริ่มต้นที่ปรับเองได้ ไม่ใช่การรับประกันการลดน้ำหนักหรือเพิ่มกล้ามเนื้อ และไม่มีการพยากรณ์ว่าจะถึงเป้าหมายในกี่วัน

การประมาณอัตโนมัติใช้สำหรับผู้ใหญ่อายุ 18 ปีขึ้นไป ไม่ครอบคลุมการตั้งครรภ์/ให้นมบุตรหรือความต้องการทางการแพทย์เฉพาะ ระบบไม่เสนอการลดน้ำหนักเมื่อ BMI ปัจจุบันหรือ BMI ของน้ำหนักเป้าหมายต่ำกว่า 18.5 รับเป้าหมาย 1,000–10,000 kcal/วันและคำนวณ TDEE ได้เฉพาะช่วงนี้ ขอบเขตตัวเลขเป็นการจำกัด input ของแอป ไม่ได้ยืนยันว่าทุกค่าภายในช่วงเหมาะกับผู้ใช้ทุกคน

BMI เป็นเครื่องมือคัดกรอง ไม่ใช่การวินิจฉัย [CDC อธิบายเกณฑ์ BMI สำหรับอายุ 20 ปีขึ้นไป](https://www.cdc.gov/bmi/adult-calculator/bmi-categories.html) การปิด preset ลดน้ำหนักเมื่อค่าต่ำกว่า 18.5 เป็นข้อจำกัดของแอป ไม่ใช้แทนการประเมินตามอายุหรือการให้คำแนะนำทางคลินิก

## การบันทึกและการเปลี่ยนข้อมูลส่วนตัว

- Server คำนวณค่าที่แนะนำเอง ไม่เชื่อค่า TDEE หรือ snapshot ที่ส่งจาก client
- `User.goalSettings` เป็น JSONB ที่เก็บชนิดเป้าหมาย เพศ/กิจกรรม วิธีตั้งค่า TDEE ข้อมูลร่างกายขณะคำนวณ น้ำหนักเริ่มต้น และเวลายืนยัน
- ผู้ใช้ที่มีเป้าหมายเดิมเริ่มต้นด้วยค่าเดิมในโหมดกำหนดเอง การเปิดหน้าไม่บันทึกหรือแทนค่าอัตโนมัติ
- เมื่อข้อมูลร่างกายเปลี่ยน หน้าจอเสนอคำนวณใหม่ ค่าเป้าหมายที่บันทึกคงเดิมจนกดบันทึกยืนยัน น้ำหนักเริ่มต้นคงเดิมเมื่อปรับประมาณการในเป้าหมายเดิม แต่เริ่มใหม่เมื่อเปลี่ยนชนิดเป้าหมายหรือน้ำหนักเป้าหมาย

## งบอาหารและความคืบหน้า

### เป้าหมายสารอาหารต่อวัน (8 ต.ค. 2569)

หน้าเป้าหมายแสดงคาร์บ โปรตีน และไขมันจากพลังงานหลังบันทึก ทั้งโหมดใช้ค่าประมาณและกำหนดเอง โดยใช้ค่าตั้งต้นของแอปดังนี้:

| แนวทาง | คาร์บ | โปรตีน | ไขมัน |
|---|---:|---:|---:|
| รักษาน้ำหนัก / สมดุล | 50% | 20% | 30% |
| ลดน้ำหนัก | 45% | 25% | 30% |
| เพิ่มกล้ามเนื้อ | 45% | 25% | 30% |

เปอร์เซ็นต์หมายถึงสัดส่วนพลังงาน ไม่ใช่สัดส่วนน้ำหนักอาหาร คาร์บและโปรตีนใช้ 4 kcal/กรัม ไขมันใช้ 9 kcal/กรัม ตัวอย่าง 2,000 kcal ในแบบสมดุลคือ 250, 100 และประมาณ 67 กรัมต่อวัน เก็บทศนิยมในการคำนวณแล้วปัดเฉพาะตอนแสดงผล จึงอาจมีผลต่างเล็กน้อยหากนำกรัมที่ปัดกลับไปคำนวณพลังงาน

ค่าตั้งต้นอยู่ในช่วง AMDR สำหรับผู้ใหญ่: คาร์บ 45–65%, โปรตีน 10–35%, ไขมัน 20–35% ตาม [National Academies, DRI Table C-5](https://www.nationalacademies.org/read/10872/chapter/13) แต่แหล่งอ้างอิงไม่ได้กำหนดว่าแต่ละเป้าหมายต้องใช้เปอร์เซ็นต์ข้างต้น นี่เป็นการเลือกของแอปเพื่อเริ่มต้น ไม่ใช่สูตรที่เหมาะที่สุดสำหรับทุกคน การเพิ่มกล้ามเนื้อยังขึ้นกับการฝึกแรงต้านและปริมาณโปรตีนตามน้ำหนัก/กิจกรรม เช่น [ISSN position stand](https://pmc.ncbi.nlm.nih.gov/articles/PMC5477153/) กล่าวถึงประมาณ 1.4–2.0 กรัม/กก./วันสำหรับผู้ที่ออกกำลังกาย แอปยังไม่ปรับโปรตีนตามน้ำหนักเฉพาะบุคคล แหล่งปัจจัยพลังงานทั่วไป: [FDA Food Labeling Guide](https://www.fda.gov/files/food/published/Food-Labeling-Guide-%28PDF%29.pdf)

หน้าวันนี้แสดง **กินแล้ว / เป้าหมายกรัมต่อวัน** คาร์บสีส้ม โปรตีนสีแดง ไขมันสีเหลือง แท่งเทียบเป้าหมายแทนการแสดงสัดส่วนสารอาหารในอาหารที่กินแล้ว ตัวเลขเกินเป้ายังแสดงจริง แต่ความยาวแท่งไม่เกิน 100% หากสารอาหารไม่ครบจะแสดง “— / ข้อมูลไม่ครบ” หรือ “~ / บางส่วน” และไม่เติมแท่งหลอกว่าเป็นข้อมูลครบ

เป้าหมาย derive จาก `dailyCalorieTarget` และ `goalSettings.mode` เดิม ไม่เพิ่มคอลัมน์หรือ payload ใหม่ ไม่เปลี่ยน TDEE หรืองบอาหารจากการออกกำลังกาย พรีวิวเปลี่ยนระหว่างเลือกได้ แต่หน้าวันนี้อัปเดตหลังบันทึกสำเร็จเท่านั้น เป้าหมายเดิมที่ยังไม่มี mode ใช้แบบสมดุลพร้อมคำอธิบายโดยไม่เขียนข้อมูลกลับ หากไม่มีพลังงานเป้าหมายจะแสดงปริมาณที่กินและ “ยังไม่ได้ตั้งเป้าสารอาหาร” วันที่ย้อนหลังเทียบกับเป้าหมายปัจจุบัน เพราะยังไม่มีประวัติเป้าหมายรายวัน

เป้าหมายใหม่เทียบพลังงานอาหารกับเป้ารับประทานโดยตรง เพราะ TDEE รวมกิจกรรมแล้ว การบันทึกออกกำลังกายจึงไม่เพิ่มงบอาหารซ้ำ ตัวเลขอาหาร/ออกกำลังกาย/สุทธิยังดูประกอบได้ บัญชีที่ยังไม่ยืนยันเป้าหมายรูปแบบใหม่คงการคิดจากพลังงานสุทธิเดิมเพื่อไม่เปลี่ยนความหมายข้อมูลย้อนหลังโดยเงียบ ๆ

กราฟน้ำหนักแสดงน้ำหนักเริ่มต้น ปัจจุบัน เป้าหมาย ผลต่าง และเส้นเป้าหมาย การเปลี่ยนน้ำหนักไม่ใช่ผลวัดมวลกล้ามเนื้อ สรุป 7 วันเทียบกับ **เป้าหมายปัจจุบัน** ไม่อ้างว่าเป็นเป้าหมายที่ใช้ในวันนั้น เพราะยังไม่มีประวัติเป้าหมายรายวัน วันที่ไม่มีอาหารแสดงเป็นไม่มีบันทึก ไม่ถือว่ากินศูนย์หรือสำเร็จตามเป้า ค่าเฉลี่ยใช้เฉพาะวันที่มีอาหารบันทึกและอาจยังเป็นข้อมูลไม่ครบทุกมื้อ

## โค้ดและการปล่อยรุ่น

- `src/shared/goals.ts`: การประมาณ TDEE/preset งบพลังงาน และการตรวจ profile ที่เปลี่ยน
- `src/client/GoalPanel.tsx`: ยืนยันเป้าหมายและปรับเอง
- `src/client/DashboardPanel.tsx`, `HealthTrendPanel.tsx`, `WeeklySummaryPanel.tsx`: สรุปตามเป้าหมาย
- Migration `20261006130000_add_goal_settings` เพิ่มคอลัมน์ nullable เท่านั้น ไม่แก้เป้าหมายหรือบัญชีเดิม

ก่อนรัน server รุ่นใหม่กับฐานจริง ต้องให้ผู้รับผิดชอบฐานข้อมูลใช้ connection ที่มีสิทธิ์ migration รัน `npm run db:migrate` หลังตรวจรายการ migration ที่ค้าง จากนั้น `npm run db:generate` และ build ใหม่ ใน Windows ให้หยุด dev API ก่อน generate หาก Prisma DLL ถูก process เดิมล็อก ไม่ต้อง seed ฐานร่วมซ้ำ สำหรับรายการอาหารใหม่ใช้ `npm run db:catalog:update` ตาม [คู่มือ catalog](food-catalog.md)

การทดสอบ migration และการเพิ่ม catalog ต้องใช้ฐาน PostgreSQL ชั่วคราวแยกจาก Supabase ของทีม การ deploy รูปแบบ Docker ต้อง build image tag ใหม่หลังการเปลี่ยนโค้ดและตรวจ schema ให้พร้อมก่อนเปลี่ยน image บน Render ดู [คู่มือ deployment](deployment/render-docker.md)
