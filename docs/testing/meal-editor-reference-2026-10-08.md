# หน้าแก้ไขและตรวจสอบอาหารตาม reference — 8 ต.ค. 2569

ปรับ presentation บน branch `feature/Chayakorn05` ใน shared meal editor จึงใช้ร่วมกันทั้งการกรอกเอง ตรวจภาพอาหาร แก้รายการจากประวัติ และแก้รายการของวันที่เลือกในหน้าแรก คง callback, validation, API และสูตรเดิมไว้

## สิ่งที่เปลี่ยน

- รูปอาหาร 80–88px สี่เหลี่ยมจัตุรัสพร้อมชื่ออาหารที่แก้ได้ ใช้ input/upload/camera เดิม ปุ่มเปลี่ยนรูปและลบรูปอยู่ใต้ส่วนหัว ภาพ catalog ที่เป็นเพียงภาพอ้างอิงยังใช้ข้อจำกัดการลบตาม flow เดิม
- ช่องมื้อและวันที่อยู่แถวเดียวกัน จอ 320px แยกเป็นสองแถว วันที่แสดงภาษาไทยผ่าน overlay บน native `input[type=date]` เพียงจุดเดียว ลบ helper วันที่ซ้ำออก คงค่า การเปลี่ยนวัน และ native calendar indicator เดิม
- พลังงานรวมเด่นขึ้น การ์ดสารอาหารเท่ากันสามใบ ใช้ส้ม/แดง/เหลืองและค่าที่คำนวณจากข้อมูลเดิม ไม่ใส่ตัวเลขจากภาพ reference เป็นข้อมูลจริง
- **ข้อกำหนดรอบแรก (ถูกแทนที่ภายหลัง):** รูปส่วนประกอบ 48px ใช้เฉพาะ URL ที่มากับ catalog match จริง ถ้าไม่มีรูปใช้ `UiIcon` แบบเดียวกัน ไม่สร้างรูปอาหารหรือค้นรูปจากอินเทอร์เน็ต. สรุปผลสุดท้ายอยู่ในหัวข้อ “ปรับล่าสุด: เอารูปส่วนประกอบออกตามผู้ใช้” ด้านล่าง
- ชื่อส่วนประกอบ 14px น้ำหนัก 600 สูงสุดสองบรรทัด kcal อยู่ด้านขวา ช่องกรัม 76px สูง 44px พร้อมหน่วยใกล้ช่อง เก็บ source badge และรายละเอียดเดิม ลบใช้สีแดง
- ลด shadow ของแถวอาหารและการ์ดโภชนาการ รายละเอียดขยายอยู่ภายในการ์ด ปุ่มรายละเอียดและลบยังแตะได้ 44px
- ปุ่มเพิ่มส่วนประกอบ คำนวณใหม่ บันทึกและยกเลิกห่างกัน **8px** ปุ่ม save สูง **50px** และยังอยู่เหนือเมนูล่างเมื่อเลื่อนถึงท้ายหน้า คงชื่อแท็บล่าสุด “หน้าแรก / บันทึก / ความคืบหน้า / บัญชี”

## ผลตรวจ

### ปรับล่าสุด: เอารูปส่วนประกอบออกตามผู้ใช้

- เอา thumbnail และ placeholder icon ออกจากรายการส่วนประกอบทุกแถวใน shared meal editor ทั้งกรอกเอง ตรวจภาพและแก้ไขมื้อ คงรูปอาหารหลักและข้อมูล catalog เดิม
- ชื่อและ kcal ใช้แถวบนเต็มความกว้าง แถวล่างจัดช่องปริมาณพร้อมหน่วย / source และรายละเอียด / ลบ โดยตัดคอลัมน์รูปออก จอแคบจัด source และรายละเอียดซ้อนกันเพื่อไม่บีบช่องกรัม
- ช่องกรัมและ action ยังมีพื้นที่แตะ 44px ปุ่มท้ายฟอร์มยังห่าง 8px ไม่แก้ callback, validation, การคำนวณหรือ API
- `meal-editor-reference.spec.ts` และ `compact-ui-fixes.spec.ts`: 5/5 ผ่าน ตรวจ 320/360/390/533/1440px รวมรายละเอียดที่ขยาย ชื่อยาว การเพิ่ม/ลบ/แก้ปริมาณ คำนวณใหม่ บันทึกล้มเหลวเก็บ draft และบันทึกสำเร็จ
- ปรับ assertion ไม่ให้มีรูปส่วนประกอบแม้ catalog มี image URL; `npm run build` ผ่าน
- จอ 320px: แถวปกติ 104.19px ชื่อยาวสองบรรทัด 122.38px (เดิม 134px); จอ 533px: 82.19px และ 100.38px ตามลำดับ ไม่มี horizontal overflow
- หลักฐานภาพเว็บจริง: `.local/meal-editor-reference-20261008/live-5173-no-ingredient-images.png`

### ตรวจซ้ำบนเว็บที่ผู้ใช้เปิด (port 5173)

- พบว่า Vite port 5173 ส่ง CSS ของ editor รุ่นเก่า แม้ไฟล์บนดิสก์เป็นรุ่นใหม่แล้ว: fieldset gap 9px และปุ่มเพิ่ม/คำนวณยังมี margin-bottom 18px ทำให้ภาพบนเว็บไม่ตรงกับ fresh test server
- แยก `meal-editor-refresh.css` เป็น CSS module ที่ import โดยตรงท้าย `main.tsx` แทน nested import ใน Tailwind entry เพื่อให้ Vite โหลดและติดตามการเปลี่ยนไฟล์นี้โดยตรง
- ลดแถวส่วนประกอบอีกเมื่อ viewport ตั้งแต่ 480px โดยให้ thumbnail กินสองแถวร่วมกับข้อความและช่องปริมาณ ไม่เพิ่มความสูงแยกสำหรับรูป
- ตรวจรายการอาหารเดิมผ่าน UI จริงที่ port 5173, viewport 542px: ส่วนประกอบ 10 รายการสูง **82.19px** ทุกแถว ปุ่มเพิ่ม/คำนวณ/บันทึก/ยกเลิกห่าง **8px / 8px / 8px** ไม่มี horizontal overflow ไม่บันทึกหรือลบข้อมูลจริง
- หลักฐานภาพ: `.local/meal-editor-reference-20261008/live-5173-footer.png`
- Fixtures ที่ 533px: แถวทั่วไป 82.19px แถวชื่อยาวสองบรรทัด 100.38px; จอ 390px ยังคง 112px และ 320px 134px เพื่อคงพื้นที่แตะและไม่ให้ข้อความชนกัน
- รันชุด targeted 5 tests ผ่านหลังปรับ CSS และตรวจ production build ผ่าน; เพิ่ม assertion ระยะ CTA 8px และขนาดแถวตั้งแต่ 480px ไม่เกิน 104px

- `npm run build` ผ่าน ทั้ง client/server typecheck และ production build มีคำเตือนเดิมจาก Zod annotation และ bundle ขนาดใหญ่
- `npx playwright test --config .local/compact-regression.config.ts`: **68/68 ผ่าน** บน Vite port 5312 ด้วย Chrome และ API fixtures
- หลังเก็บขนาดปุ่มเปลี่ยนรูป/สีพลังงานและย่อข้อความปุ่มคำนวณ รัน `meal-editor-reference.spec.ts` กับ `compact-ui-fixes.spec.ts` ซ้ำ: **5/5 ผ่าน** คง accessible name เดิมของปุ่มคำนวณ
- ตรวจที่ 320/360/390/533/1440px ไม่มี horizontal overflow ชื่อไม่ชน kcal รูปอาหาร ratio 1:1 และช่องกรัมอ่านได้ การ์ด 10 รายการสูง 112px ที่ 390/533px และ 134px ที่ 320px ภาพส่วนประกอบขยายจาก 36px ของรอบก่อนเป็น 48px ตาม reference ใหม่
- ตรวจชื่อ มื้อ วันที่ การเปลี่ยน/ลบรูป การเพิ่ม/ลบ/แก้ปริมาณจริงผ่าน callback เดิม การคำนวณ 643.5 → 708.5 → 825.5 kcal ของ fixture เมื่อแก้ปริมาณ/ลบ/เพิ่ม และ request PUT ไปยัง id เดิม ไม่มีการสร้างมื้อซ้ำ
- บันทึกถูก disable หลังแก้ส่วนประกอบจนกดคำนวณใหม่ บันทึกล้มเหลวยังคงชื่อ วันที่และส่วนประกอบ บันทึกสำเร็จกลับหน้าหลักพร้อมข้อความยืนยัน
- `git diff --check` ผ่าน ไม่เปลี่ยนข้อมูลบัญชีจริง ไม่เรียก provider AI จริง และยังไม่ได้ deploy ผลนี้ไม่ยืนยัน native picker บนทุกเบราว์เซอร์/อุปกรณ์จริง
