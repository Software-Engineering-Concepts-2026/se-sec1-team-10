# LifeBalance: ผลทดสอบกับบริการจริงก่อนเตรียม deploy

ตรวจวันที่ 6 ตุลาคม 2569 บน `feature/Chayakorn05` ที่ commit `a0c2f3b` ซึ่งตรงกับ `life-balance-test` หลังรวม PR #61 และ #63 ใช้หน้าเว็บ Vite ที่ `http://127.0.0.1:5173` และ API ของโปรเจกต์ที่พอร์ต 3000 เชื่อม PostgreSQL บน Supabase ตามการตั้งค่าในเครื่อง ไม่รัน migration หรือ seed และไม่แก้ข้อมูลสมาชิกทีม

## ผลที่ยืนยันกับระบบจริง

| สิ่งที่ตรวจ | ผลและหลักฐาน |
| --- | --- |
| สมัครสมาชิกและล็อกอิน | API ผ่าน และการกดผ่านหน้าเว็บผ่าน ใช้บัญชี QA ชั่วคราวที่สร้างเฉพาะรอบทดสอบ |
| ข้อมูลส่วนตัวและ session | บันทึกอายุ น้ำหนัก ส่วนสูง แล้วรีเฟรช หน้าเว็บยังล็อกอินและอ่านค่าที่บันทึกกลับมาได้ |
| ค้นหาอาหารจาก catalog | พบ `banana` ใน Supabase; การประมาณจาก catalog ใช้ข้อมูลอ้างอิง 89 kcal ต่อ 100 กรัม และไม่ใช้โควตา AI |
| ปริมาณและสารอาหาร | บันทึกกล้วย 200 กรัมได้ 178 kcal; แก้เป็น 100 กรัมได้ 89 kcal ตรวจสารอาหารที่มีค่าอ้างอิงและอ่านผลแก้ไขกลับจากประวัติ |
| เพิ่มและลบส่วนประกอบ | ผ่านหน้าเว็บจริง: เพิ่มอาหารจาก catalog สองรายการ ลบหนึ่งรายการ ปรับรายการที่เหลือเป็น 150 กรัม คำนวณและบันทึก ตรวจข้อมูลและแคลอรีที่เก็บด้วย Prisma |
| รูปหลังบันทึก | ตรวจค่า imageData ใน MealLog บน Supabase ตรงกับรูปที่ส่ง และอ่านกลับผ่าน API ได้ หน้าเว็บมีรูปในประวัติหลังรีเฟรช |
| ใช้มื้ออาหารเดิม | เปิดมื้อจากประวัติเพื่อนำกลับมาใช้ แบบฟอร์มมีชื่อ ปริมาณ 150 กรัม และรูปเดิม |
| การแยกข้อมูลบัญชี | บัญชี QA อีกบัญชีอ่านไม่เห็นรายการของบัญชีแรก; แก้และลบรายการของอีกบัญชีไม่ได้ (404) |
| session หลังออกจากระบบ | คำขอที่ไม่มี session ถูกปฏิเสธ (401) และ cookie เดิมใช้ต่อไม่ได้หลัง logout |
| AI รูปอาหารจริง | ส่งภาพข้าวกับไก่หนึ่งครั้ง ได้ส่วนประกอบเป็นกรัม การวิเคราะห์ไม่สร้าง MealLog จนกดบันทึก ผลบันทึกคิดจากผลรวมส่วนประกอบ |

การทดสอบ API จริงผ่าน 7 กลุ่ม การทดสอบหน้าเว็บกับ Supabase จริงผ่าน 2 tests ใน `e2e-live/app.spec.ts` ไม่มีการ mock catalog ในการทดสอบนี้ รอบสุดท้ายเก็บ API response ที่ status ตั้งแต่ 500 และ browser page errors เพิ่มด้วย โดยไม่พบทั้งสองอย่าง ชุด live tests ผ่านการตรวจ TypeScript และ `git diff --check` บัญชี QA และข้อมูลที่สร้างในรอบนี้ถูกลบแล้ว รวมบัญชีชั่วคราวจากการรันที่ cleanup ถูก sandbox บล็อกในตอนแรก

## ผล AI รอบนี้

ใช้ภาพ Wikimedia Commons [Home-cooked Hainanese chicken rice.jpg](https://commons.wikimedia.org/wiki/File:Home-cooked_Hainanese_chicken_rice.jpg) ของ Kcdtsg/David ซึ่งเป็น public domain และปรับขนาดไว้ที่ 768 × 576 พิกเซล เรียกบริการ AI หนึ่งครั้งโดยไม่มีการ retry อัตโนมัติ

AI ตั้งชื่อว่า `ข้าวราดไก่ต้มซีอิ๊ว` และให้ข้าว 280 กรัม ไก่ติดกระดูก 180 กรัม กับซอส 35 กรัม ข้าวจับคู่กับ catalog ได้ ส่วนไก่และซอสใช้ `ai-estimate` ผลรวมที่บันทึกคือ 726 kcal เวลาตั้งแต่ส่งวิเคราะห์จนตรวจ preview และบันทึกเสร็จประมาณ 16.5 วินาที ค่านี้รวมงาน API และฐานข้อมูล จาก timing log ของ API เวลารอ provider คือ 13.7 วินาที และการวิเคราะห์รวม quota กับ catalog คือ 14.1 วินาที

การทดสอบยืนยันการเชื่อมต่อ รูปแบบผลตอบกลับ การยืนยันก่อนบันทึก และการคำนวณจากส่วนประกอบ ไม่ได้ยืนยันว่าชื่อเมนู น้ำหนัก หรือสารอาหารที่ AI เดาถูกต้องทั้งหมด ผู้ใช้ยังต้องตรวจและแก้ผลก่อนบันทึก

## ขอบเขตและสิ่งที่ต้องทดสอบต่อ

- ทดสอบ browser ที่ viewport 390 × 844 บนเครื่องคอมพิวเตอร์ ยังไม่ได้ลองกล้องและการอนุญาตบนมือถือจริงผ่าน HTTPS
- รูปปัจจุบันเก็บเป็น data URL ใน `MealLog.imageData` ของ PostgreSQL บน Supabase ยังไม่ได้ใช้ Supabase Storage
- ยังไม่ได้ทดสอบ URL deploy, production cookies, network ภายใน Docker, restart บนเครื่อง hosting หรือ backup/restore
- ก่อน deploy ต้องตรวจค่าการเชื่อมต่อและการเปิดรับ network ของ API ให้ตรงกับสภาพแวดล้อมจริง

ตอนเริ่มตรวจ API ไม่ได้รัน และหน้าเว็บหยุดระหว่างเตรียมทดสอบ จึงเปิดบริการใหม่ก่อนเก็บผลจริง ส่วนข้อผิดพลาด sandbox และรูปแบบคำขอใน harness รอบแรกไม่ใช่ผลทดสอบฟังก์ชันที่ผ่าน รายงานนี้ใช้ผลรอบที่รันกับบริการจริงสำเร็จเท่านั้น

ระหว่างรอบเตรียมทดสอบ API มี log `PrismaClientKnownRequestError` สองรายการที่ไม่มี endpoint หรือ error code จึงระบุสาเหตุไม่ได้ ในรอบสุดท้ายที่เก็บ API 5xx และ browser errors ไม่พบอาการดังกล่าว แต่หลักฐานนี้ยังไม่ยืนยันว่าปัญหาฐานข้อมูลทุกชนิดถูกแก้แล้ว

หลักฐาน API แบบไม่รวมรหัสหรือ session อยู่ใน `.local/live-system-api-20261006-result.json` บนเครื่องที่ใช้ทดสอบ ไฟล์ `.local` ไม่ถูกส่งขึ้น Git
