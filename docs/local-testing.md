# เปิดและทดสอบ LifeBalance ในเครื่อง

แอปต้องใช้ PostgreSQL ส่วนการวิเคราะห์รูปและการค้นข้อมูลจาก USDA เป็นตัวเลือกเสริม ให้ตั้งค่าใน `.env` ของเครื่องโดยไม่ส่งค่าจริงให้ผู้อื่น

## เตรียมแอปและฐานข้อมูล

ติดตั้ง dependencies และตั้ง `.env` โดยคัดลอก `.env.example` แล้วกำหนด `DATABASE_URL` ให้ชี้ไปยัง PostgreSQL ที่ได้รับอนุญาตให้ใช้ พร้อมตั้ง `JWT_SECRET` เป็นค่าสุ่มยาวอย่างน้อย 32 ตัวอักษร จากนั้นสร้าง Prisma Client:

```sh
npm ci
npm run db:generate
```

เลือกแนวทางฐานข้อมูลให้ตรงกับที่ใช้งาน:

- **ฐานข้อมูลร่วมที่ทีมเตรียม schema ไว้แล้ว:** ใช้ `DATABASE_URL` ที่ได้รับอนุญาต รันเพียงคำสั่งด้านบน ไม่ต้องรัน migration หรือ seed ซ้ำ
- **ฐานข้อมูลใหม่หรือฐานข้อมูล local:** ถ้าใช้ Docker ให้เปิด PostgreSQL ด้วย `docker compose up -d db` แล้วรัน `npm run db:migrate` ก่อนใช้งาน รัน `npm run db:seed` เฉพาะเมื่อต้องการข้อมูลตัวอย่าง

## เปิดแอป

```sh
npm run dev
```

หน้าเว็บอยู่ที่ `http://127.0.0.1:5173` และ API อยู่ที่ `http://127.0.0.1:3000`

## การทดสอบ

- `npm run build` ตรวจ TypeScript และสร้างเว็บกับ API
- `npm test` รัน unit และ API tests; ชุดนี้ไม่ต้องใช้ฐานข้อมูลจริง
- `npm run test:e2e` รันเบราว์เซอร์กับ API จำลองที่ port 5174 โดยไม่ใช้ AI key, โควตา หรือฐานข้อมูล
- `npm run test:e2e:chunks` ใช้หน้าเว็บที่ build แล้วและ Vite preview ที่ port 5186 ทดสอบการกู้คืนเมื่อ lazy chunk โหลดไม่สำเร็จ ให้รัน `npm run build` ก่อน; API ถูก mock จึงไม่ใช้ฐานข้อมูลจริง
- `npm run test:e2e:live` ใช้ Microsoft Edge กับแอปที่กำลังรันบน `http://127.0.0.1:5173` และ PostgreSQL จริงจาก `.env`; คำสั่งนี้ไม่เปิดแอปให้เอง ให้เปิด `npm run dev` ใน terminal อีกหน้าต่าง และใช้ฐานข้อมูลทดสอบแยกต่างหากเท่านั้น เพราะชุดทดสอบสร้างบัญชีและมื้ออาหารจริง แม้มีขั้นตอนลบบัญชีทดสอบท้ายชุดก็ตาม ชุดนี้ไม่ได้รันใน CI

อย่าเผยแพร่ `.env` หรือใส่รหัสผ่าน, connection string, API key หรือ secret จริงในเอกสารและ `.env.example`
