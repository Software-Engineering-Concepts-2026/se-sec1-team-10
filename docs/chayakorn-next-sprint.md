# แผนรอบถัดไป: งานอาหารบน branch ของชยากร

จัดทำ 20 กันยายน 2026 ตามคำขอให้ Terra เป็นผู้พัฒนาหลัก, Luna ทำงานย่อย และ Astra วางทิศทาง/ตรวจรับหลังส่งมอบ

สถานะ: เริ่มดำเนินการบน `feature/Chayakorn05` แล้ว โดยอัปเดตแบบ fast-forward จากฐานร่วม `7888563` หลังตรวจ remote; PR เดิม #53 จะใช้ `life-balance-test` เป็นปลายทางตามคำสั่งผู้ใช้ ไม่มีการรวมเข้า main

## 1. เป้าหมายของรอบงาน

ทำให้ผู้ใช้เพิ่มอาหารจาก AI หรือฐานข้อมูล → ตรวจรายการ → ปรับปริมาณ/เปลี่ยนหรือลบส่วนประกอบที่ผิด → กดคำนวณใหม่ → บันทึก → เปิดแก้ภายหลัง ได้โดยปริมาณและสารอาหารไม่เพี้ยน

ทำเฉพาะงานอาหารของชยากรและส่วนข้อมูลร่วมที่จำเป็นสำหรับงานนี้ ไม่รับงานบัญชี/เป้าหมาย/กราฟของเพื่อนมาทำทั้งหมด และไม่รื้อโครงสร้างรอบใหม่

ข้อบกพร่องที่ยืนยันจากการอ่านโค้ดปัจจุบัน:

- API และ Prisma เก็บเฉพาะชื่อ/สารอาหารของส่วนประกอบ ยังไม่เก็บปริมาณหรือฐานคำนวณ; เปิดแก้แล้ว UI ตั้งเป็น 100 กรัม
- ผล AI ไม่มีน้ำหนักส่วนประกอบ แต่ UI ใช้เป็นข้อมูลต่อ 100 กรัม
- ค่าขาดหายจากฐานข้อมูลอาหารถูกแปลงเป็น 0 ใน helper บางจุด ต้องแยก “ไม่มีข้อมูล” ออกจากค่าศูนย์จริง
- ปุ่มคำนวณใหม่ปลดสถานะก่อนบันทึก แต่ผลรวมเปลี่ยนทันทีขณะกรอก
- flow เพิ่มเองยังไม่มีทางระบุอาหารและค่าตั้งต้นครบเมื่อไม่มี AI/USDA
- รายการโปรดเก็บรูปแบบเดิมใน localStorage ต้องรองรับข้อมูลเดิมเมื่อเปลี่ยนโครงสร้าง

## 2. เตรียม branch ก่อนเริ่ม

ชื่อจริงที่พบในเครื่องคือ `feature/Chayakorn05` ซึ่งเป็น branch ที่ผู้ใช้เรียกว่า chayakorn05 ใช้สาขานี้ ไม่สร้างชื่อใหม่ซ้ำ

ฐานโค้ดร่วมหลังจัดระเบียบคือ `9deb855`; หัว `life-balance-test` ขณะวางแผนคือ `7888563` ซึ่งเพิ่มเฉพาะเอกสารข้อตกลงฐานร่วม ผลตรวจ local refs คือ branch ส่วนตัวมี commit เฉพาะตัว 0 และตามหลัง 18 commits ตัวเลขนี้ยังไม่ได้ยืนยันกับ remote ล่าสุด

ขั้นตอนเมื่อเริ่มพัฒนาจริง:

1. ตรวจ working tree และเก็บงานค้างของผู้ใช้ไว้ โดยเฉพาะ `.vite/`, `debug.log`, `.env` ไม่ stage เหมารวม
2. Fetch remote แล้วตรวจทั้ง local/remote `feature/Chayakorn05` และ `life-balance-test` อีกครั้ง เพื่อไม่ทิ้งงานที่ถูก push จากเครื่องอื่น
3. หาก branch ส่วนตัวเป็นบรรพบุรุษของฐานร่วมและไม่มีงานแยก ให้ switch ไปสาขาส่วนตัวแล้วอัปเดตแบบ fast-forward only หากพบประวัติแยก ให้รายงาน commits ที่ต่างก่อนเปลี่ยนประวัติ; ห้าม reset หรือ force-push
4. บันทึก hash ฐานเริ่มงานไว้ในรายงานรอบนี้ ให้เพื่อนใช้ฐานร่วมเดียวกันเมื่อเริ่มสาขาของตน
5. นำแผนนี้ไปกับชุดงาน แล้ว commit/push งานรอบใหม่เฉพาะ `feature/Chayakorn05` ตามขอบเขตล่าสุดของผู้ใช้

การอัปเดตฐานเป็นการรับโค้ดเดิมเข้ามา ไม่ใช่ผลงานใหม่ของผู้รับ branch และไม่ใช่การรวมผลงานรอบนี้เข้า `main` การเปิด PR หรือรวมกลับสาขาทดสอบต้องมีคำสั่งแยกจากผู้ใช้

## 4. ข้อตกลงข้อมูลที่ต้องจบใน P1

Terra จัดตัวอย่างข้อมูลก่อนเขียน migration โดยยึดหลักต่อไปนี้:

- ส่วนประกอบมีชื่อ, ปริมาณที่เลือก, หน่วย, ปริมาณอ้างอิง, สารอาหารต่อปริมาณอ้างอิง และแหล่งข้อมูล เช่น AI/USDA/ข้อมูลเดิม
- ข้อมูล USDA ใช้ฐานต่อ 100 กรัม; ข้อมูล AI ต้องบอกปริมาณและหน่วยที่รองรับ ห้ามสมมติว่าหนึ่งจานเท่ากับ 100 กรัม
- สูตรคือ `สารอาหารสำหรับปริมาณที่เลือก = ค่าสารอาหารอ้างอิง × ปริมาณที่เลือก ÷ ปริมาณอ้างอิง` ใช้สูตรเดียวกันฝั่ง client/server หรือ shared module เพื่อไม่ให้ผลต่างกัน
- ปริมาณอ้างอิงต้องมากกว่า 0 ตรวจตัวเลขจำกัดช่วงและไม่รับ NaN/Infinity; ไม่บวกน้ำตาลซ้ำกับคาร์โบไฮเดรตในการคิดพลังงาน
- ข้อมูลเก่าที่ไม่ทราบน้ำหนักคงยอดเดิมและใช้หน่วย “ส่วนเดิม” ไม่แปลงเป็นกรัมโดยไม่มีหลักฐาน เก็บ migration ให้อ่านรายการเก่าได้โดยไม่ลบข้อมูล
- ค่าที่ไม่ทราบไม่แทนด้วย 0 ไม่แสดงพลังงานรวมว่าแน่นอนถ้าข้อมูลที่ใช้คำนวณยังไม่ครบ; กำหนดให้ผู้ใช้เลือกแหล่งข้อมูลที่ครบก่อนบันทึกยอดโภชนาการในรอบนี้
- server ตรวจและคำนวณยอดบันทึกจากปริมาณ/ฐานที่รับและผ่าน validation ไม่เชื่อยอดรวมที่ client ส่งมา ทั้งนี้การรับ metadata แหล่งข้อมูลไม่ได้ทำให้ค่าที่ผู้ส่งแก้ไขกลายเป็นค่าที่ตรวจสอบแล้ว
- migration ออกแบบเพิ่ม field ที่รองรับข้อมูลเก่า คงสารอาหารเดิมไว้จนย้ายครบ พร้อมทดสอบ rollback ทางโค้ด/การอ่านข้อมูลเก่า ไม่ reset ฐานจริง

P1 ถือว่าเสร็จเมื่อมีตัวอย่าง USDA 200 กรัม, AI ที่ทราบปริมาณ, ข้อมูลเก่าที่ไม่ทราบกรัม และข้อมูลที่สารอาหารไม่ครบ พร้อมผลลัพธ์ที่คาดหวัง จากนั้นจึงให้ Luna ลงมือ UI ตาม contract นี้

## 7. แผนทดสอบและการใช้โควตา

- ระหว่างพัฒนา รัน test เฉพาะพฤติกรรมที่เปลี่ยนและ typecheck หลังเปลี่ยน contract ไม่รันทั้งชุดทุกครั้งที่แก้ข้อความ
- ก่อน P6 รัน `npm test`, `npm run build`, `npm run test:e2e` หนึ่งรอบบนโค้ดที่นิ่งแล้ว เก็บ exit code และจำนวนผ่าน/ข้ามจริง
- ตั้งฐานข้อมูลทดสอบแยกสำหรับ migration/round-trip แล้วทดสอบเพิ่ม แยกหลักฐาน DB จริงจาก API จำลอง หากยังรัน DB ไม่ได้ให้นับ P2 ว่ายังตรวจรับไม่ครบ
- ใช้ภาพ/คำตอบจำลองสำหรับ AI ในการพัฒนา; ทดสอบกับ API มหาวิทยาลัยจริงเพียงรอบสุดท้ายเมื่อจำเป็น ตั้งเพดานเริ่มต้น 3 รูปและไม่ retry อัตโนมัติไม่จำกัด ใช้สิทธิ์ทดสอบที่ผู้ใช้เคยให้ไว้
- ผล AI จริงใช้ยืนยันว่าเชื่อมต่อและรูปแบบข้อมูลใช้ได้ ไม่ใช้เป็นหลักฐานว่าสารอาหารจากภาพแม่นยำทั้งหมด
- Astra อ่าน diff, contract และผลทดสอบตอน checkpoint ไม่อ่าน repository ทั้งหมดซ้ำ หากพบปัญหาส่งกลับเฉพาะชุดงานที่เกี่ยวข้อง แล้วทดสอบซ้ำเฉพาะผลกระทบ

## 8. รูปแบบมอบหมายงานให้ agent

แต่ละงานต้องมีข้อมูล 6 อย่าง: เป้าหมาย, branch, รายชื่อไฟล์ที่แก้ได้, contract/ตัวอย่างข้อมูล, เกณฑ์ผ่าน, สิ่งที่ต้องส่งกลับ

ตัวอย่างงาน Luna ใน P3:

> บน feature/Chayakorn05 ปรับ MealIngredientEditor ให้รับข้อมูลตาม contract P1 ที่ Terra สรุป ปรับได้เฉพาะส่วนประกอบ/ปริมาณและปุ่มคำนวณ ห้ามแก้ schema, routes หรือ MealPanel โดยไม่ประสาน เมื่อเปลี่ยนปริมาณ/ลบ/แทนที่ต้องแจ้ง parent ผ่าน callback และบันทึกไม่ได้จนคำนวณใหม่ ทดสอบด้วย fixture ที่ตกลง รายงานไฟล์ที่แก้ กรณีที่ผ่าน สิ่งที่ยังติด แล้วหยุดแก้เพื่อให้ตรวจรับ ห้าม commit/push เอง

ตัวอย่าง handoff ของ Terra:

> P2/P4 เสร็จ: contract รุ่น …, ไฟล์ …, migration …, ผลทดสอบพร้อม exit code …, ข้อจำกัด …, สิ่งที่ reviewer ต้องดู …; ไม่มีคำสั่งหรือ agent ที่ยังแก้ไฟล์อยู่

## 9. การส่งงานให้เพื่อน

- ส่ง hash ฐานร่วม, ข้อตกลงข้อมูลส่วนประกอบใหม่ และ migration ที่ต้องรัน ให้ทีมผ่านเอกสาร/ข้อความที่ผู้ใช้เลือกส่ง
- งาน B (บัญชี/ตั้งค่า) และ C (กิจกรรม/กราฟ) เป็นของเพื่อนบน branch ของตน ไม่ใช่งาน Luna ที่ต้องไปแก้ข้าม branch
- หาก C ใช้ยอดอาหาร ให้ประสาน response summary ว่ายังมี field เดิมใดบ้าง และตรวจว่าข้อมูลไม่ครบจะถูกแสดงอย่างไร
- จบแต่ละชุดที่ build ได้ด้วย commit ตามหน้าที่ เช่น persistence, UI, regression tests ไม่ใส่ไฟล์ส่วนตัว/key
- จบ P6 รายงาน commit บน `feature/Chayakorn05`, ผลทดสอบ, migration/setup, ข้อจำกัด และสิ่งที่พร้อมให้เพื่อนใช้ ยังไม่เปิด PR หรือรวมเข้าสาขาอื่นโดยอัตโนมัติ
