# LifeBalance — UI Design Brief

อัปเดตตาม working tree ของ branch `feature/Chayakorn05` วันที่ 9 ต.ค. 2569 เอกสารนี้เป็นขอบเขต UI ปัจจุบันสำหรับพัฒนาต่อ ไม่ยืนยันว่า Render deploy โค้ดชุดนี้แล้ว รายงานวันที่ก่อนหน้าใน `docs/testing/` เป็นหลักฐานของแต่ละรอบ ไม่ใช่ข้อกำหนดที่ต้องนำกลับมาใช้

## หลักการและขอบเขต

คง 4 แท็บ **หน้าแรก / บันทึก / ความคืบหน้า / บัญชี** ใช้ component, callback, API, validation และ calculation เดิม ปรับภาพและ layout ได้โดยไม่เพิ่ม feature หรือแต่งข้อมูลตาม mockup ไม่มี QR/barcode scanner, Settings รวมศูนย์, share, rating, swipe, social sign-in หรือ image search

ใช้รูปอาหารที่มีในข้อมูลจริงเท่านั้น หากไม่มีใช้ placeholder เดิม ส่วนประกอบอาหารไม่มีรูปหรือ placeholder ตามคำขอผู้ใช้ ข้อมูลไม่ครบต้องแสดงสถานะ ไม่แต่งค่าเป็นศูนย์

ใช้ฟอนต์ Noto Sans Thai ในโปรเจกต์ การ์ดขาว พื้นหลังอ่อน ข้อความหลักเข้ม action หลักเขียว ปุ่มลบแดง และข้อความกำกับสถานะ ไม่สื่อด้วยสีอย่างเดียว รักษา label, focus, keyboard access และพื้นที่แตะประมาณ 44px

## หน้าแรก (Today ในโค้ด)

- โลโก้อยู่หน้าคำทักทาย ชื่อผู้ใช้และ avatar ใช้ข้อมูลบัญชีจริง
- Date selector แถวเดียว: ลูกศรซ้าย 44px → date bar ที่ย่อได้ → ลูกศรขวา 44px ตรงกลางเปิด native date picker ลูกศรขวาปิดเมื่ออยู่วันนี้ เลือกวันใหม่โหลดข้อมูลของวันนั้นผ่าน flow เดิม
- สรุปพลังงานใช้วงแหวนด้านซ้าย คงเหลือ/เกินเป้าและสารอาหารหลักด้านขวา รายละเอียดเสริมเปิด/ปิดได้
- สารอาหารหลักใช้ไอคอน SVG รวงข้าว/เนื้อ/หยดน้ำมัน 20px ในวงกลม pastel 36px สีส้ม/ชมพู/เหลืองอ่อน ไอคอน ชื่อและ bar ใช้สีของ macro ส่วนตัวเลขใช้สีข้อความหลัก ไม่เพิ่ม card แยกแต่ละ macro
- แสดงปริมาณกินแล้ว / เป้าหมายกรัมจาก `dailyMacroTargets` เดิม bar สูง 7px เติมไม่เกิน 100% แต่ตัวเลขเกินเป้ายังแสดงครบ ข้อมูลไม่ครบแสดงสถานะและไม่เติม bar เสมือนครบ
- ส่วนอาหารหัวเรื่อง “อาหาร · วันที่” จำนวนรวม และปุ่มเพิ่มรายการอยู่ด้านขวาของหัวเดียวกัน ใช้ฟอนต์กระชับ คงปุ่มบันทึกด้านล่าง
- แยกรายการเป็นเช้า → กลางวัน → เย็น → ของว่าง แสดงเฉพาะกลุ่มที่มีอาหารพร้อมจำนวนและ kcal รวม ข้อมูลเก่าที่ไม่ทราบมื้อยังมีที่แสดง
- การ์ดอาหารในหน้าแรกมีรูป/placeholder ชื่อ ส่วนประกอบย่อ kcal และ action แก้ไข/ลบของเดิม การ์ดหลักและแก้ไขเปิด editor เดิม ปุ่มเพิ่มใช้วันที่ที่กำลังดู
- เพิ่ม/แก้/ลบย้อนหลังได้ บันทึกสำเร็จกลับวันเดิมและโหลดสรุปใหม่ การเปลี่ยนวันที่ใน editor ไม่เลื่อนวันที่หน้าแรก ลบต้องยืนยันและคงรายการถ้า API ผิดพลาด

เป้าหมายกรัมคำนวณจากพลังงานและ mode ปัจจุบัน วันที่ย้อนหลังไม่ได้ใช้ประวัติเป้าหมายรายวันเพราะไม่มีข้อมูลนั้น กฎพลังงานของเป้าหมายใหม่และบัญชีเดิมคงเดิม ดู [เป้าหมายและสูตร](../goals.md)

## บันทึกอาหาร

หน้าเริ่มมี search พื้นขาวและ action กล้อง/กรอกเอง/กิจกรรมเป็นปุ่มแยก ไม่มีแถบวันนี้/เมื่อวาน/เลือกวันที่ ประวัติล่าสุดย้อนหลัง 30 วัน ปุ่มดูทั้งหมดเปิดประวัติเต็ม และมีโหลดเพิ่มตาม pagination เดิม

search ค้นประวัติของผู้ใช้และ catalog; catalog ต้องมีอย่างน้อย 2 ตัวอักษรและแสดงแหล่งข้อมูล/พลังงานต่อ 100 กรัม รายการสารอาหารไม่ครบยังเลือกบันทึกไม่ได้ loading/error/retry/empty แยกตามกลุ่ม

### การ์ดประวัติอาหาร

- รูปอาหาร/placeholder ซ้าย 80px radius 10px ตามขนาดในโค้ดล่าสุด
- ชื่อหนา 15px หนึ่งบรรทัดพร้อม ellipsis และชื่อเต็มใน title ตามโค้ดปัจจุบัน
- กรัมรวมเมื่อทุกส่วนประกอบเป็นกรัม ตามด้วย kcal และ badge มื้อ
- `+` ขวาบนเปิด draft สำหรับบันทึกซ้ำ; แก้ไขและลบขวาล่างใช้ action เดิม
- พื้นขาว radius 16px padding แนวตั้ง 6px / แนวนอน 12px border อ่อน ไม่มีเส้น action แยกแถวเพิ่มความสูงโดยไม่จำเป็น

ทั้งประวัติล่าสุดและประวัติเต็มใช้ `MealHistory` ร่วมกัน การแก้เปิดวันที่ของรายการเดิม การใช้ซ้ำยังต้องตรวจวันที่/มื้อและกดบันทึกเอง

## กล้อง

preview ใช้ความสูงพื้นที่ระหว่างหัวหน้ากับเมนูล่าง เผื่อ safe area ไม่ล็อกความสูงแบบการ์ดเล็ก กรอบนอก preview และแถบควบคุมไม่มีมุมมน คงกรอบจัดอาหารด้านใน ปุ่มกลับ อัลบั้มและชัตเตอร์เดิม หากกล้องไม่พร้อมปิดชัตเตอร์และมีข้อความพร้อมทางเลือกอัลบั้ม

ถ่าย/เลือกภาพสำเร็จเปิด editor โหมดภาพ ไม่ส่งวิเคราะห์ AI อัตโนมัติ และคงรูปเมื่อวิเคราะห์ผิดพลาด

## ตรวจสอบ/แก้ไขอาหารร่วมกันทุกทางเข้า

ลำดับ: รูปหลัก + ชื่อที่แก้ได้ → มื้อ/วันที่ → พลังงานรวม → คาร์บ/โปรตีน/ไขมัน → ส่วนประกอบ → เพิ่ม/คำนวณใหม่/บันทึก/ยกเลิก

- รูปหลัก 80–88px ratio 1:1 มี action เปลี่ยน/ลบรูปตาม flow เดิม
- มื้อและวันที่ใช้สองช่อง จอแคบย่อ/stack ได้ วันที่ไทยแสดงจุดเดียวบน native date picker ไม่พิมพ์ซ้ำใต้ field
- Energy card เด่นกว่า macro 3 ช่อง ข้อมูลทั้งหมดใช้ผลคำนวณจริง
- ส่วนประกอบใช้แถว compact ไม่มีรูป ชื่อ/kcal แถวบน ปริมาณพร้อมหน่วย แหล่งข้อมูลสั้น รายละเอียดและลบแถวล่าง ชื่อยาวต้องไม่ชน kcal
- Source badge ระบุค่าประมาณ AI, catalog, USDA, manual หรือข้อมูลเดิมตามข้อมูลจริง รายละเอียดขยายเมื่อกด ไม่มี image search หรืออาหารทดแทน
- เพิ่ม/ลบ/แก้ปริมาณทำให้รอคำนวณใหม่และปิด save ตามกฎเดิม ปุ่มท้ายหน้าห่าง 8px save สูง 48px และไม่ชนเมนูล่าง
- สำเร็จกลับหน้าหลักของส่วนที่เปิดพร้อมข้อความยืนยัน; ล้มเหลวคงข้อมูลและชี้ข้อผิดพลาด ไม่เพิ่มการเก็บ draft ถาวรข้าม reload

โหมดกรอกเองแนบรูปได้โดยไม่วิเคราะห์ภาพ การเพิ่มส่วนประกอบด้วยชื่อใช้ catalog ก่อนแล้วอาจใช้ AI ตาม flow เดิม โหมดภาพต้องกดวิเคราะห์เอง วิเคราะห์ใหม่ตามชื่อที่แก้ใช้โควตาและแทนส่วนประกอบเดิมเมื่อสำเร็จ ต้องแสดงคำเตือนก่อนกด

## ความคืบหน้า

หัวเรื่อง → น้ำหนักเริ่มต้น/ปัจจุบัน/เป้าหมาย/ผลต่าง → น้ำหนักหรือ BMI → ช่วงเวลา → กราฟ → ประวัติน้ำหนักย้อนหลัง 1 ปี → สรุปพลังงาน 7 วัน

มีบันทึก/แก้ไข/ลบน้ำหนักโดยตรง วันที่ไม่เกินวันนี้และย้อนหลังภายใน 1 ปี ต้องมีส่วนสูงก่อนเพิ่มเพื่อคำนวณ BMI กราฟใช้รายการล่าสุดของแต่ละวัน ประวัติยังแสดงรายการเดิมที่เก็บอยู่ ไม่มีการ์ด “ข้อมูลเพิ่มเติม” ที่ซ้ำส่วนสูง/BMI อยู่ระหว่างประวัติกับสรุปสัปดาห์

สรุป 7 วันเลือกวันสิ้นสุดได้ สีเขียวรับประทาน สีส้มเผาผลาญ ไม่ใช่สีเกินเป้าหมาย วันที่ไม่มีอาหารแสดงว่าไม่มีข้อมูล ค่าเฉลี่ยใช้วันที่มีบันทึก และเปรียบเทียบกับเป้าหมายปัจจุบัน

## บัญชีและหน้าลูก

- หน้าหลักแสดง avatar ชื่อ email ปุ่มเปลี่ยน/ลบรูปแนวเดียวกัน และ “ดูข้อมูลโปรไฟล์” สำหรับข้อมูลร่างกายที่กดขยายได้ ไม่แสดงน้ำหนัก/ส่วนสูง/BMI ซ้ำตลอดเวลา
- เมนูข้อมูลส่วนตัว เป้าหมายสุขภาพ แจ้งเตือนมื้ออาหาร และออกจากระบบ ไม่มีเฟืองหรือ route ตั้งค่าใหม่
- ข้อมูลส่วนตัวแก้ชื่อ อายุ น้ำหนัก ส่วนสูง รูปโปรไฟล์ต้องกดบันทึกรูปแยกตาม flow เดิม
- เป้าหมายมี 3 mode, เพศสูตร, กิจกรรม, ค่าแนะนำ/กำหนดเอง และน้ำหนักเป้าหมาย แยกส่วนตั้งค่ากับพรีวิว TDEE/พลังงานหลังบันทึก/สัดส่วน macro คงสูตรเดิม ไม่เปลี่ยนเป้าหมายอัตโนมัติเมื่อน้ำหนักเปลี่ยน
- บันทึกข้อมูลส่วนตัว/เป้าหมายสำเร็จกลับบัญชีและแจ้งยืนยัน ถ้าผิดพลาดคงฟอร์ม
- แจ้งเตือนเก็บใน localStorage ของบัญชีบนอุปกรณ์นี้ เวลาแก้แล้วบันทึกทันที ต้องอนุญาต notification และเปิดเว็บไว้ ไม่มี push เมื่อปิดแอปหรือ sync ข้ามเครื่อง

## Responsive และสถานะผิดพลาด

มือถือใช้ลำดับแนวตั้ง desktop ตั้งแต่ 1024px ใช้พื้นที่กว้างและสองคอลัมน์ในส่วนที่มี style รองรับ เช่น สรุป/รายการอาหาร และกราฟ/ประวัติ คง 4 แท็บเดิมทุกขนาด ไม่สร้างหน้าหรือปุ่มจากพื้นที่ว่าง

ตรวจ 320/360/390/768/1440px ไม่ให้ horizontal overflow ชื่อยาวและค่ามากไม่ชนปุ่ม พื้นที่แตะและ native date/time inputs ยังใช้ได้ error/loading/empty มีคำอธิบายและ retry ตาม component เดิม

`LazyPanelBoundary` แสดงทางออกเมื่อ chunk/หน้าโหลดไม่สำเร็จและแจ้งว่า reload อาจทำข้อมูลยังไม่บันทึกหาย ไม่ reload อัตโนมัติ หรือเพิ่ม draft persistence
