## A — อาหารและ AI: ชยากร

ไฟล์หลัก: `src/client/MealPanel.tsx`, `FoodSearchPanel.tsx`, `FavoriteMealsPanel.tsx`, `FoodHistoryPanel.tsx`, `favorites.ts`, `src/server/ai.ts`, `nutrition.ts`, `meal.ts`

งานแรกตามลำดับ:

1. กำหนดข้อมูลส่วนประกอบให้มีปริมาณ หน่วย ค่าสารอาหารอ้างอิง และแหล่งที่มาอย่างชัดเจน ประสาน schema/API กับผู้ดูแลไฟล์ร่วม
2. แก้การนำผล AI ไปใช้: response ปัจจุบันไม่มีน้ำหนักส่วนประกอบ แต่ UI กำหนดเป็น 100 กรัมและถือว่าสารอาหารเป็นค่าต่อ 100 กรัม จึงยังไม่มีหลักฐานรองรับหน่วยนั้น ต้องให้ AI ส่งปริมาณที่ประมาณไว้พร้อมค่าต่อปริมาณนั้น หรือใช้หน่วยสัดส่วนมื้อจนกว่าจะทราบน้ำหนัก ห้ามแสดงน้ำหนักที่ระบบไม่มีข้อมูล
3. เก็บปริมาณและฐานคำนวณลงฐานข้อมูล รวมถึงรายการโปรด ปัจจุบัน payload บันทึกเก็บเฉพาะชื่อและสารอาหาร และเมื่อเปิดแก้ UI ตั้งปริมาณกลับเป็น 100 กรัม
4. ทำ flow เพิ่มอาหารเมื่อ AI ใช้ไม่ได้ให้จบได้จริง ปัจจุบันรายการเริ่มว่างและ 0 สารอาหาร แต่ไม่มีช่องแก้ชื่อส่วนประกอบหรือแหล่งสารอาหารในแถวนั้น ต้องออกแบบให้เลือกอาหารที่มีข้อมูลอ้างอิงได้ โดยยังแก้เองเฉพาะปริมาณตาม UX ที่ตกลง
5. ตกลงพฤติกรรมปุ่ม “คำนวณสารอาหารใหม่”: ปัจจุบันผลรวมเปลี่ยนทันที และปุ่มเพียงปลดสถานะก่อนบันทึก หากต้องการคำนวณเมื่อกดจริง ให้แยกค่าที่กำลังแก้กับผลที่ยืนยันแล้ว

เกณฑ์ส่งงาน: เลือกอาหาร 200 กรัม → บันทึก → โหลดใหม่ → เปิดแก้ แล้วยังเห็น 200 กรัมและยอดเดิม; เปลี่ยนเป็น 100 กรัมแล้วสารอาหารลดครึ่งหนึ่งโดยใช้ฐานเดิม; ลบส่วนประกอบแล้วผลรวมถูกต้อง; ไม่มี key/timeout ของ AI ก็แสดงทางไปต่อที่ใช้งานได้; มี test ครอบคลุมการบันทึกและอ่านกลับจริง

## B — บัญชีและตั้งค่า: จิตตินี

ไฟล์หลัก: ส่วนบัญชีใน `src/client/App.tsx`, `GoalPanel.tsx`, `ReminderPanel.tsx`, `reminders.ts`; งาน API ใช้ส่วน auth/profile/goals ใน `src/server/app.ts` โดยประสานผู้ดูแลไฟล์ร่วม

1. เสนอแยกหน้าบัญชีเป็น `AccountPanel.tsx` ให้ `App.tsx` เหลือการประกอบหน้าและ session เป็นหลัก ทำทีละขั้นโดยรักษาพฤติกรรมเดิม
2. ตรวจสมัคร/ล็อกอิน/ออกจากระบบ และโปรไฟล์ที่กรอกไม่ครบหรือค่าผิดช่วง
3. ตรวจหัวข้อตั้งค่าที่กดเปิด–ปิด การบันทึกเป้าหมาย และข้อมูลหลัง refresh
4. ทดสอบการอนุญาต/ปฏิเสธแจ้งเตือนบนมือถือจริง พร้อมข้อความอธิบายข้อจำกัด การแจ้งเตือนขณะปิดแอปเป็นงานเพิ่มเติมที่ต้องตกลงก่อน

เกณฑ์ส่งงาน: ตั้งค่าเริ่มแบบย่อ; บันทึกแล้ว refresh ไม่หาย; error อยู่ใกล้ช่องที่ผิด; ออกจากบัญชี A แล้วบัญชี B ไม่เห็นข้อมูล/การตั้งค่าของ A; การปฏิเสธแจ้งเตือนไม่ทำให้หน้าใช้ไม่ได้

## C — กิจกรรมและความคืบหน้า: ภัทรพล

ไฟล์หลัก: `src/client/ExercisePanel.tsx`, `DashboardPanel.tsx`, `HealthTrendPanel.tsx`, `WeeklySummaryPanel.tsx`, `src/server/exercise.ts`, `health.ts`, `src/shared/activities.ts`; API สรุปผลอยู่ใน `src/server/app.ts`

1. เตรียมข้อมูลทดสอบอาหารและกิจกรรมที่ทราบยอดรวม แล้วตรวจหน้า Today และกราฟให้ตรงกัน
2. ตรวจเพิ่ม/แก้/ลบกิจกรรม ว่ายอดพลังงานและสรุปผลอัปเดต
3. ตรวจวันที่ในเขตเวลาไทย ช่วงสัปดาห์ วันไม่มีข้อมูล น้ำหนัก/ส่วนสูงที่ยังไม่กรอก และประวัติน้ำหนัก
4. ตรวจการโหลดข้อมูลย้อนหลังปริมาณมาก โดยบันทึกจำนวนข้อมูล วิธีทดสอบ และเวลาที่วัดได้

เกณฑ์ส่งงาน: กิน 600 kcal และเผาผลาญ 200 kcal ต้องแสดงสุทธิ 400 kcal; เปลี่ยนหรือลบข้อมูลแล้วทุกหน้าที่เกี่ยวข้องแสดงผลใหม่; วันไม่มีข้อมูลไม่ทำให้กราฟพัง; ไม่มีข้อมูล BMI ต้องไม่แสดงค่าเทียม; มี test API/ฐานข้อมูลและตัวอย่างผลตรวจด้วยมือ

## วิธีใช้ branch ส่วนตัว

1. ตรวจและเก็บงานค้างใน branch ส่วนตัวเดิมก่อน อย่า reset หรือเขียนทับประวัติ
2. ตกลงฐานเดียวกันก่อนเริ่ม หากแต่ละ branch ต้องมีเฉพาะงานตัวเองจริง ๆ อย่านำ `life-balance-test` ทั้งก้อนเข้าไป เพราะจะพางานทุกส่วนติดไปด้วย ให้เทียบกับ branch เดิมและเลือกเฉพาะ commits/ชุดไฟล์ที่เกี่ยวข้อง พร้อม dependency โดยผู้รวมงานตรวจร่วมกัน
3. ถ้าทีมยอมรับโค้ดปัจจุบันเป็นฐานร่วม สามารถให้สาขาส่วนตัวเริ่มจากฐานนั้นได้ แต่ต้องระบุว่าเป็นโค้ดฐานเดิม งานของแต่ละคนคือการเปลี่ยนแปลงหลังฐาน ไม่ใช่ทุกไฟล์ใน branch
4. ในช่วงนี้ยังไม่ได้เลือกหรือดำเนินการย้ายฐานแบบใด และยังไม่มีการแก้ branch ส่วนตัว
5. แต่ละคน commit งานจริงในชื่อของตัวเอง ส่งชื่อ branch, commit hash, รายการไฟล์, ผลทดสอบ และข้อจำกัดให้ผู้รวมงาน
6. นำงานมาทดสอบรวมใน `life-balance-test` เมื่อเจ้าของโครงการสั่งให้รวม ห้ามเปิด PR หรือ merge เข้า `main` อัตโนมัติ

ตัวอย่างสรุปส่งงาน: “B-โปรไฟล์: บันทึกอายุและน้ำหนักแล้วโหลดกลับได้ แก้ AccountPanel และ profile test; build ผ่าน; ทดสอบ API จริงผ่าน; ยังไม่ทดสอบ iOS; commit …”

## ตรวจรับและเอกสารประกอบ

- รัน `npm test` และ `npm run build`; งาน UI รัน `npm run test:e2e` เพิ่ม ชุด UI นี้ใช้ Edge และ API จำลอง
- งานฐานข้อมูล/API ต้องมีผลทดสอบกับฐานข้อมูลทดสอบจริง ดู [local-testing.md](local-testing.md); การผ่าน API จำลองอย่างเดียวไม่ยืนยันการบันทึกจริง
- ใช้ Docker สำหรับ PostgreSQL ตาม `compose.yaml`; เว็บและ API ยังเปิดด้วย Node.js ไม่ได้อยู่ใน Compose นี้
- ไม่ใส่ key จริงใน `.env.example` และไม่ส่ง `.env` ให้เป็นส่วนหนึ่งของ commit
- อ่าน [คู่มือโครงสร้างโค้ด](team-development-guide.md) และ [ตั้งค่า AI](ai-setup.md)
- หมายเลข Issue ในคำแนะนำก่อนหน้ายังไม่ใช่การตรวจ assignee/สถานะล่าสุด ให้ตรวจเฉพาะ Issue ที่เปิดอยู่และตกลงกับเจ้าของก่อนผูกชุดงาน A/B/C เอกสารนี้ไม่ได้เปลี่ยนสถานะ Issue ใด
